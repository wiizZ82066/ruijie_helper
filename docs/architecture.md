# 架构与兼容边界

本文介绍公开源码的实现方法，不包含个人账号、机器标识、安装路径或真实现场报告。推荐入口为 `campus_flet.py`；原厂客户端及驱动由使用者已有的安装提供，不随项目分发。

## 组件划分

| 组件 | 职责 |
| --- | --- |
| `campus_flet.py` | 自适应 Flet 界面、异步后台任务、统一状态反馈和日志脱敏 |
| `utils/auth_service.py` | 与界面无关的认证、配置、自启动和热点操作 |
| `utils/ui_tasks.py` / `instance_guard.py` | 操作互斥、迟到查询失效及与旧版共用的单实例保护 |
| `utils/flet_runtime.py` | 固定桌面运行时校验及本机 IPC 对端身份检查 |
| `campus_authenticator.py` | 保留的 PySide6 界面 |
| `utils/client_discovery.py` | 从有效用户选择、服务注册和有限安装候选发现客户端 |
| `utils/core_patch.py` / `core_install.py` | 版本校验、局部修改、备份、原子替换和服务恢复 |
| `utils/auth_credentials.py` | 将输入的账号转换为受支持核心的原生配置格式 |
| `utils/auth_runtime.py` | 启动核心并按进程会话及新结果判断认证 |
| `utils/auth_log.py` | 解析本次核心会话新产生的明确认证通知 |
| `utils/credential_store.py` | 当前用户 DPAPI 凭据保存 |
| `utils/hotspot.py` / `hotspot_validation.py` | 共享来源选择、Windows WinRT 热点控制及状态验证 |

| `utils/network_diagnostics.py` | 本地只读诊断 |
| `utils/native_adapters.py` | 通过 Windows IP Helper 只读枚举网卡，失败时由调用方回退到 PowerShell |

## 原生分析与版本限制

静态分析区分启动界面、服务和实际认证核心，检查 PE 导入、字符串引用、相关函数及调用者。实际认证、EAPOL 收发、心跳和本地策略检查均位于原生核心中，不能把它当作登录后可随意移除的检测附件。

兼容修改针对代码中已核验的 RG-SU 6.61 文件，涉及 `CheckHomeShare`、`CheckMulNICDevice` 及代理检测启用分支，共改变 8 个字节。实现同时校验整文件摘要和局部原始指令；不在未知版本上搜索相似字节并套用修改。修改保留原认证协议和心跳路径，不意味着恢复了完整源码，也不证明所有策略都已覆盖。

受支持服务从其安装目录管理认证核心，因此将修改可恢复地应用于原安装路径。安装先写入可校验备份及恢复记录，再停止受路径约束的服务和核心，原子替换并校验。服务无法常规停止时，后备流程仍核验服务注册路径与精确进程身份，并恢复原启动类型及运行状态。未知目标文件不覆盖。

## 账号输入和凭据保存

GUI 中的校园账号、密码作为内存对象传递，不进入普通设置文件、日志或子进程命令行。“在本程序记住账号密码”将两字段一起交给 Windows 当前用户 DPAPI 加密，以原子方式保存。无法解密现存库时拒绝静默覆盖，只有明确清除操作才能重置。

为了复用原核心，账号准备仍需写入原生配置。兼容层恢复其外层编码、DES-CBC 密码格式和机器绑定材料派生，沿用现有网卡与认证参数模板。机器材料只在本地使用，不记录或上传。原生配置并非 DPAPI 库，用户目录和配置仍保留账号标识；清除本程序凭据不会删除这些记录。

账号准备在受控服务停止期间写入配置、采样结果基线并按普通启动路径创建新核心会话，再恢复服务。配置写入异常时尝试在当前进程内回滚；尚未提供跨崩溃的原生配置事务恢复。

## 认证状态

核心会话由进程标识与创建时间共同确定，并核验可执行文件路径。结果必须对应此会话且满足时间、文件更新和一致性检查，不能只看到残留的 `Succeed` 就判断本次登录成功。

原核心部分成功回调不更新结果文件，因此还通过 `utils/auth_log.py` 检查本次会话新产生的固定认证成功、失败和断开事件，并按事件顺序判断；日志历史或普通网络可达性不能单独作为本次认证成功的依据。

日志游标在账号准备期间、创建新核心之前采样，核对文件身份、偏移、边界和完整记录。日志头中的 `P` 是线程标识，使用只读 Windows API 确认其所属认证进程；不将它误当作进程标识。轮转、截断或读取失败使旧证据失效，新的失败或断开记录也不能被旧成功结果覆盖。

原核心可能先产生暂时失败再自行连接。等待逻辑保持原会话，直到新成功、超时或取消；不因暂时失败重新提交账号或重启进程。一旦本次认证出现失败，不能回退到历史成功结果。会话退出或被替换时拒绝复用其结果。

显式选用原客户端保存账号的兼容方式，可在严格的同会话条件下结合选定实体有线接口的联网状态验证已有认证。输入新账号的流程不走历史成功兜底。

## 热点来源与验证

有线接口用于校园网认证。检测到唯一可用的 Clash/Mihomo TUN 时，共享来源选择该 TUN，以避免错误使用物理出口转发；无活动 TUN 时使用所选有线接口。来源有歧义或缺少必要路由、连接配置时拒绝启动。

热点使用 WinRT 明确指定共享来源和实体无线设备，按接口标识去重保存的无线配置，并在操作前重新核验动态状态。接口由运行时枚举和用户选择确定，不依赖固定网卡名称或机器标识。

验证有两条路径：

- 经典 ICS：系统返回完整、无矛盾的公共与私有共享配对。
- 本程序启动的现代 WinRT：明确观察到本次从关闭状态成功开启，且来源、实体无线设备和后续私有接口身份一致；同时核查地址、路由、共享服务和上游状态。

现代路径不要求一定存在旧式 COM 标志，但不能忽略明确的 COM 冲突、读取错误或被替换的私有接口。每次新的开启操作重新建立归属证据，不能用旧缓存认领外部已有热点。新开的热点验证失败时，仅在有本次启动归属证据且无明确身份变化时尝试回滚；已有热点不擅自替换或自动关闭。

Windows 未提供可直接核对的热点代际标识，本版本无法识别外部程序在两次观察之间关闭并以相同接口标识重建热点的情况。状态验证也不代表终端已经获得地址、解析域名或访问互联网。

## 旧 Electron 后端

保留的旧界面通过 Electron 主进程代理访问本机 FastAPI 后端。每次启动生成临时随机令牌，通过子进程环境传入；主进程附加 Bearer 鉴权，渲染页面不持有令牌。后端不开放通配跨域访问，缺失或错误会话凭据的请求在配置读取或系统操作前被拒绝。

该后端不是公开服务，也不应脱离桌面会话无鉴权运行。接口只允许启动发现安装目录中的认证核心，网卡操作通过参数列表执行，不将网卡名称拼入 shell。

## 构建与公开范围

默认构建采用 PyInstaller 目录模式，运行库位于程序旁的 `_internal`，减少每次启动的解包开销。Flet 构建只提供目录模式；保留的 Qt 构建脚本另提供可选单文件模式。

Flet 界面的热点状态和自启动查询独立在后台执行，不参与登录就绪条件；读取期间可以输入账号密码。改变网络的操作按顺序执行，热点状态读取与热点变更共享资源锁。过期查询不能覆盖新操作结果，顶部和底部提示通过同一入口脱敏并更新。网卡枚举使用系统接口提供的硬件标志和类型，不根据名称推断实体网卡；原生接口不可用或数据不符合预期时回退到原有查询。

固定 Flet 0.86.5 运行时在构建时下载，使用已固定的官方归档和文件清单摘要校验，随包提供；程序启动时不下载依赖。桌面内部使用回环 TCP IPC，通道本身不加密。连接守卫通过操作系统核验对端属于本次创建的 Flutter 子进程，并检查进程创建时间、父进程及可执行路径；不会将它作为无鉴权 HTTP 服务开放到网络。关闭可能记录控件值的框架日志。

公开仓库只保留可复用源码、合成测试和公开文档。原厂二进制、私人分析与现场采样、账号库、原生用户配置、恢复备份及本地诊断不属于公开内容。离线回归使用合成数据和模拟系统边界，不操作实际账号或网络。
